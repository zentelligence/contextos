# Web server shutdown

`contextos-web` handles Ctrl+C and, on Unix, SIGTERM (including `systemctl --user stop contextos-web`). Signals are registered before startup connections begin; cancellation during a stalled handshake also closes sessions that already connected. It stops the scheduler and accepting new HTTP connections, allows existing requests up to 10 seconds to drain, and then closes all connected MCP sessions concurrently with a 10-second cleanup deadline. A timeout produces a warning identifying the affected server, without logging credentials or request contents.

For stdio, shutdown closes the server's stdin first. The transport waits up to three seconds for EOF-driven exit. On POSIX it then sends SIGTERM to the process group and allows another three seconds before SIGKILL; on Windows it terminates the job object after the EOF grace period. Forced termination has a two-second reap deadline. Stdout remains drained during cleanup so final output cannot block exit. Cleanup runs in an independently owned task, shielded from caller cancellation. Unix children run in separate process groups, so terminal interrupts cannot bypass this sequence; forced cleanup also targets launcher descendants. On Windows, children use a separate console process group and a job object for process-tree cleanup. HTTP cleanup closes streams and, for a server on a revision before 2026-07-28 that issued a session, requests deletion of that session; the SDK bounds session deletion to five seconds. A 2026-07-28 connection has no session, so nothing is deleted. A remote server that does not support session deletion does not prevent local shutdown.

Installed systemd units use `KillMode=mixed` and `TimeoutStopSec=30`: SIGTERM initially reaches only the web process, with systemd retaining a final whole-control-group kill deadline. Existing installations must run `contextos-web service install` again to update their unit. Custom units should carry these same settings.

The deadline bounds cleanup; it does not guarantee completion of long-running requests or background jobs. Jobs interrupted during shutdown may require the existing job-state recovery procedure. SIGKILL and forced operating-system termination cannot be handled gracefully. Windows Task Scheduler's forced termination, and `contextos-web service stop` on Windows, are not console shutdown events.

## Change contract and verification

Graceful shutdown is bounded. It changes no MCP tool, HTTP route, or configuration schema. Session operations retain the SDK's transport trait boundary and do not alter the vault write pipeline.

Regression coverage exercises real Unix process-group SIGINT and SIGTERM delivery, stdin EOF before host exit, shared session ownership, HTTP session deletion, an unresponsive HTTP deletion with virtual time, SIGTERM before forced killing, cancellation-shielded process-tree termination, repeated closure, and generated systemd settings. The initial signal tests failed with signal exit statuses, and the initial shared-session test failed because shutdown left the session open. Completion checks are `just ci` and `.claude/scripts/check.sh`; native macOS and Windows signal handling require their respective platform runs.
